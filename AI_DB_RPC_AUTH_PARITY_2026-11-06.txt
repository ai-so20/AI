[0. 실행 범위와 결론]
두 Supabase 프로젝트의 information_schema / pg_proc / pg_class / pg_policies / FK 메타데이터와 GitHub 로그인 소스를 읽기 전용으로 확인했다. 운영 데이터 쓰기, 권한 수정, 스키마 생성, cron 변경, Vercel 환경변수 변경, 원본 26 수정 없음.
판정: 26과 AI는 이름이 비슷한 테이블이 일부 있지만 AI PROCESS, 출석, 상품 재고, 지급 테이블의 계약이 서로 다르다. 두 DB를 교체 연결하거나 26 관리자를 그대로 복제해서 운영할 수 없다. 공통 함수 이름만으로 동일 동작 보장 불가.
주의: 실제 계정 E2E·외부 API 무단 조회 가능 여부·Auth UUID 교차 DB 일치성은 검증하지 않았다.

get_admin_private_chats, mark_private_chat_read, run_auto_event_engine은

3. AUTH / 로그인 / 회원 ID
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[원본 26 /v2 회원 입장]
  nickname + realName 입력.
  POST /api/auth/member-entry → 서버에서 승인된 profiles id 확인 →
  같은 Supabase 프로젝트의 Auth 사용자 조회 및 magiclink OTP 확인 →
  session 발급 → supabase.auth.setSession.
  승인 상태 비교 '1'.

[신규 AI 루트 / 회원 로그인]
  nickname + password 입력.
  POST /api/auth/login → 프로필 nickname으로 id 확인 →
  같은 AI Supabase 프로젝트의 Auth 사용자 이메일 조회 →
  signInWithPassword → session 발급 → setSession.
  승인 상태 비교 'approved'.
  vip-ui-locked는 세션 삭제가 아니라 기존 UI 잠금으로 사용.

[검증 가능한 집계만]
  26: Auth 사용자 수 43, public.profiles 43, 인증 사용자/프로필 자체 DB 조인 누락 0 (조회 당시).
  AI: profiles 승인 회원 33명(관리자 1 + 회원 32, 앞선 읽기 전용 조회값).
      AI Auth 사용자별 조인 집계는 안전 검사로 조회가 차단되어 검증 못함.
  개인 이메일, 비밀번호, 사용자 ID 원문, 서비스 비밀키는 이 보고서에 수집/저장하지 않았다.

중요: 양쪽 Auth는 별도 프로젝트에서 토큰과 사용자 ID를 발행한다.
'닉네임이 같다'는 이유만으로 Auth UUID를 동일하다고 판단하거나
profiles 행을 복사해 통합하면 안 된다. 교차 프로젝트 UUID 대응은 미검증.
인증 방식을 통합하려면 회원 계정과 역할/승인, 세션 처리, 데이터 소유권, RLS를
한꺼번에 설계하고 테스트해야 한다.

4. RLS / PUBLIC DATA SECURITY — 우선 검토 필요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[26 확인]
  events, event_entries, event_game_secrets, event_reward_deliveries,
  attendance_records 등은 RLS ON.
  해당 테이블의 정책이 0개인 항목도 있음. 테이블 직접 조회가 아니라
  권한 제어된 RPC 흐름을 통해 처리할 가능성을 별도로 검사할 것.
  private_messages, profiles 등은 RLS ON + 정책 존재.

[AI 확인]
  events, event_entries, event_game_secrets, event_reward_deliveries,
  event_gift_inventory, event_prize_catalog, attendance_records 등 RLS OFF.
  이들 테이블에 anon 및 authenticated 역할의 SELECT 테이블 권한이 부여된 상태 확인.
  특히:
    events.quiz_answer             : 이벤트 정답 컬럼
    event_game_secrets.secret_answer: 비공개 정답 컬럼
    event_gift_inventory.gift_url  : 기프티콘 URL 컬럼
  RLS OFF + anon SELECT 권한 조합은 Supabase Data API에 노출되는 경우
  비로그인 요청으로 정답/상품 URL을 읽을 수 있는 보안 위험이 있음.
  외부에서 실제 엔드포인트 조회를 시도하지 않았으므로 현재 '위험 확인',
  실제 공개 데이터 유출 확정 아님.
  회원 접근 정책 검증 전 원본 데이터/기프티콘/당첨 함수를 AI DB에 복사 금지.

[권한 주의]
  has_table_privilege는 테이블 권한이며, RLS 및 실제 Data API 노출,
  API schema 제한을 대체하지 못함. 권한·정책·API 설정을 함께 점검해야 한다.
