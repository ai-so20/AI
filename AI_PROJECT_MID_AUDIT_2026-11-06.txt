1. 결론
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
화면 구조/내용/일부 클라이언트 기능의 이식은 진행됐으나, 26과 같은 운영 데이터 계약을 사용하지 않으므로 현재는 '전체 기능 이식 완료'가 아니다.
원본 26과 신규 AI의 Supabase가 완전히 다른 프로젝트다. 원본 26의 테이블·RPC를 그대로 호출하는 신규 페이지 중 실제 AI DB에 해당 자산이 없는 것들은 동작 불가다.
Vercel READY는 빌드 배포 성공이지, 회원 실사용·관리자 운영 성공이 아니다.
사용자는 디자인은 전체 기능 이식 후 최종 검수할 예정. 홈은 하단 주식·코인 부분 외 임의 변경하지 말 것.

2. 중간 비교표: 구조 / 구성 / 내용 / 기능 / 실제 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[홈 /design-home]
- 구조: 신규 홈과 메뉴 5개로 구성. 기존 26 홈의 기능을 그대로 가져온 상태는 아님.
- 이식: 하단 주식·코인 8개 자산 가격/AI 상태·판단 문구·최근 변화 표시 (원본 26 계산 헬퍼 활용). 메뉴는 각 /design- 경로로 연결.
- 남은 부분: 상단 자산·수익 예시값은 정적 시안. 상단과 일반 디자인은 사용자 지시로 지금 변경 금지. 실제 회원 UI 데이터 정확성은 미검증.
- 판정: 하단 기능 코드 일부 이식, 실데이터 연결 미확인 / 전체 홈 이식 완료 아님.

[AI PROCESS /design-ai-process]
- 구조/내용: 대기·진행·완료, 그래프, 반영 기록, 주식·코인 8개 상태 영역 구성.
- 코드: 원본 26의 getMemberProcessSnapshot, buildAiMarketStates/History 이식. 그래프 snapshot.chartPoints 사용. 3분 반영·상태 데이터 로직 원본 일치 확인.
- 데이터: 신규 페이지는 ai_process_members 조회. 실제 AI 연결 DB에는 ai_process_members 테이블이 없음. 26 연결 DB에는 있음. 실제 회원 상태 조회는 현재 연결에서 실패 예상.
- 미검증: 진행/완료 회원별 실제 값 대조 (26 DB 조회 당시 ai_process_members 2건 모두 ready).
- 판정: 계산/표시 코드 이식, 실제 운영 연결 미완료.

[이벤트 /design-event]
- 구조/내용: 당일 회차, 참여, 당첨 결과, 공개 정답, 최근 당첨 공지 조회 구현.
- 데이터: get_auto_events / join_auto_event RPC는 두 DB에 존재하지만 테이블·함수 정의의 동일성은 보증하지 않음. 최근 당첨 공지 group_messages 권한이 회원별로 제한됨.
- 미검증: 실제 회원 응모, 당첨 내역, 회원 RLS, 상품 이미지. 원본 26 DB에 이미지 URL 필드나 Storage 파일이 없어 이미지 구현을 유보함.
- 판정: 일부 클라이언트 기능 이식, 데이터/실사용 차이 검증 필요.

[출석 /design-attendance]
- 구조/내용: 누적 출석, 30회 달성 혜택, 체크 버튼, 지급 결과/상품센터 링크.
- 데이터: 원본 26 DB에 get_daily_attendance_status / check_daily_attendance RPC 존재. 신규 AI 연결 DB에는 두 RPC 없음.
- 미검증: 실제 출석, 30회 자동 보상, 상품 지급 메시지.
- 판정: 화면·호출 코드 이식, 현재 DB 연결에서는 기능 동작 불가 예상 (중요 미완료).

[상품지급센터 /design-reward]
- 구조/내용: 1:1 메시지, 읽음, 기프티콘·링크·이미지, 푸시 허용/알림, 실시간 수신 구현.
- 데이터: get_or_create_admin_chat, mark_private_chat_read, get_my_private_unread_count, get_admin_private_chats 등은 신규 AI DB에서도 확인되지만 원본 26과 완전한 정책/스키마 동일성은 미검증.
- 미검증: 사용자 메시지 전송, 실제 상품 링크, 푸시 전달, 관리자 쌍방 통신.
- 판정: 여러 기능 코드 이식, 실사용 검증 미완료.

[로그인/승인/메뉴]
- 신규 AI /에는 별도 닉네임/비밀번호 로그인과 기존 관리자 기능이 있음.
- 26 승인값 '1', AI 승인값 'approved': 신규 /design-* 화면의 체크를 양쪽 모두 인식하도록 수정.
- 기존 AI는 로그아웃 때 auth 토큰을 당장 삭제하지 않고 vip-ui-locked 플래그로 잠근다. 신규 페이지들도 잠금을 확인·감시해 회원 UI 노출을 제한.
- /design-* 내부 링크 경로 정리. / 루트 로그인 후 직전 /design-*로 자동 복귀 기능은 아직 미구현.
- 판정: 접속·권한 코드 보완, 실제 계정 E2E 미완료.

[관리자: 원본 26 /v2/admin vs 신규 AI 기존 /?tab=admin]
- 원본 26 관리자 6개 섹션: 운영 요약, 회원 관리, AI PROCESS, 상품 재고, 상품 지급/1:1, 이벤트·운영.
- 신규 AI 루트 관리 메뉴: 대시보드, 회원 관리, AI PROCESS, 이벤트, 그룹채팅, 1:1 문의.
- 주요 차이:
  회원 관리: 26의 get_admin_approval_list/admin_set_member_approval 등 vs AI의 get_admin_all_profiles/admin_set_profile_approval 등. 함수 계약 서로 다름.
  AI PROCESS: 26의 ai_process_members + admin_save_ai_process_member_preserving_profit / admin_adjust_ai_process_profit vs AI 기존의 별도 AI PROCESS 처리 서비스/세션. 같은 기능이라고 볼 수 없음.
  상품 재고: 26은 일반·AI·출석 재고 관리 RPC 3종과 전용 관리자 탭. AI 기존에는 별도 상품 카탈로그/링크 등록 흐름. 동일한 재고 관리 체계가 아님.
  상품 지급/1:1: 두 프로젝트 모두 채팅 관리자 기능 있지만 운영 정책·메시지 지급 검증 필요.
  이벤트 운영: 원본 26은 참여자/당첨 문구/그룹 운영 및 돌발 설정 등 전용 관리자 모듈. 신규 AI는 이벤트 당첨/재고/그룹 운영의 별도 구현이므로 완전 이식 아님.
- 이번 완료: /design-ai-process (관리자 상태) → 같은 AI 프로젝트 /?tab=ai,
             /design-event (관리자 상태) → /?tab=event,
             /design-attendance (관리자 상태) → /?tab=admin,
             /design-reward (관리자 상태) → /?tab=private.
- 모든 링크는 신규 AI 자체 도메인 내부 경로. 원본 26 관리자 주소로 보내지 않음. 로그인/승인/role이 admin인 경우만 표시.
- 주의: 이것은 기존 AI 관리자 화면으로 들어가는 링크를 복구한 것이며, 26 관리자 기능을 전부 이식한 것이 아님.
- 판정: 관리자 경로 보완 완료, 원본 관리자 기능 패리티 미완료.

3. 핵심 차이 / 안전 제약
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 26 Vercel NEXT_PUBLIC_SUPABASE_URL → amgeyannjsslzmoowcmd
- AI Vercel NEXT_PUBLIC_SUPABASE_URL → vyjtpushaumjedcfwxbn
- Supabase Auth 사용자 ID/승인값/테이블/RPC가 다르다. 원본 DB 연결을 바꾸는 것은 기존 회원 및 관리자 기능을 손상시킬 위험.
- 운영 DB 쓰기, 사용자·금액·수익/당첨·출석/상품 재고 변경, Cron 변경을 승인 없이 실행하지 않는다.
- 원본 26 GitHub/Vercel은 읽기 비교 전용. AI GitHub에만 코드를 수정한다.
- 현재 원본 DB와 신규 DB를 합치거나 한쪽으로 Vercel 환경변수를 바꾸지 않았다.
- 사용자 지시: 홈 다른 영역은 현 단계에서 손대지 말 것. 디자인 평가는 모든 기능 이식 뒤.

4. 다음 우선순위
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) [결정 필요] 현재 AI DB를 보존하며 별도 DB에 같은 기능을 구현할지, AI UI를 26 데이터와 읽기 전용으로 연결할지 등 연결 전략/권한 범위를 사용자가 지정하기 전까지 데이터 연동 수정 금지. 다른 프로젝트 데이터를 자동 합치지 말 것.

3) [연결 결정 후] 실사용 회원 계정으로 AI PROCESS 대기/진행/완료, 이벤트 참여·당첨, 출석·보상, 지급/알림, 관리자 모듈 E2E 검사.
4) 마지막에 사용자가 홈과 나머지 디자인 일괄 검수.
